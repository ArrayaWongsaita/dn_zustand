# ทบทวน — แยก state และค้นบั๊กข้อมูลเดิม

กิจกรรม 30 นาที: ทบทวน local/store/derived state 10 นาที → ค้นและแก้บั๊ก 15 นาที → อธิบายเหตุผลและเลือกจุดฝึกต่อ 5 นาที

เริ่มจากเฉลยบท 6: สมุด ×2 ปากกา ×1 จำนวนรายการ 2 จำนวนชิ้นรวม 3 ยอดรวม 120 บาท ตัวกรองสินค้าและ actions พร้อมใช้ ไม่ต้องทำบทล้างตะกร้าหรือ persist ก่อน และไม่เพิ่มฟีเจอร์ใหม่ในกิจกรรมนี้

## เริ่มครั้งแรกและกลับมาฝึก

อ่าน [เตรียมเครื่อง](../TOOLING.md) commit งานเดิมและหยุด dev server ก่อนเปลี่ยน branch:

```sh
git switch -c my/09-review origin/09-review-bug
npm ci
npm run dev
```

ถ้ามีแต่ local branch ให้ตัด `origin/` ออก ถ้ามี branch ส่วนตัวแล้วใช้ `git switch my/09-review` ไม่สร้างซ้ำ เก็บงานด้วย `git add src/stores/cart-store.js` และ `git commit -m "Practice review exercise"` แม้ยังไม่สำเร็จ

## 10 นาทีแรก: เลือกเจ้าของข้อมูล

เปิดโค้ดแล้วตอบด้วยเหตุผลของตัวเอง:

1. คำค้นสินค้าเป็น local state ที่ component ใดใช้ เหตุใดเปลี่ยนคำค้นแล้วตะกร้าควรเหมือนเดิม?
2. `items` และ actions เป็นข้อมูลร่วมใน store เพราะ component ใดต้องใช้งานบ้าง?
3. จำนวนรายการ จำนวนชิ้นรวม และยอดรวมเป็น derived state อย่างไร ถ้าเก็บค่าซ้ำจะต้องซิงก์เมื่อใดบ้าง?
4. สมุด ×2 ปากกา ×1 ให้จำนวนรายการ 2 แต่จำนวนชิ้นรวม 3 เพราะอะไร? เมื่อเพิ่มสมุดอีกหนึ่งชิ้นค่าไหนเปลี่ยน?

ลองค้น “ปาก” แล้วล้างคำค้น ยืนยันว่าตะกร้ายังเหมือนเดิม อธิบายว่าการกรองสินค้าให้ซื้อไม่ใช่การกรองรายการที่ซื้อแล้ว

## 15 นาที: ตรวจอาการก่อนแก้

ชุดฝึกมีบั๊กหนึ่งจุดในเส้นทางเพิ่มจำนวน หน้าจออาจแสดงสมุดจาก 2 เป็น 3 ชิ้นได้ แต่ข้อมูลตะกร้ารุ่นก่อนอาจถูกเปลี่ยนด้วย ไม่มี TODO บอกบรรทัดให้เติม ให้ใช้ test เป็นหลักฐานแล้วหาเหตุเอง ไม่แก้ tests หรือเพิ่มฟีเจอร์

```sh
npm run test:unit
npm run test:e2e
```

ใช้สองคำสั่งแยกกันเพื่อให้เห็นผลหน้าจอแม้ unit ไม่ผ่าน Playwright เปิดแอปให้อัตโนมัติ ต้องหยุด `npm run dev` ก่อนรัน ชุดฝึกตั้งต้นควรผิดเพียง `increasing quantity preserves the previous cart and its item objects` ส่วน test อื่นและหน้าจอผ่าน การที่ UI ผ่านจึงยังไม่ยืนยันว่าข้อมูลเดิมไม่เปลี่ยน

อ่านชื่อ test → expected/actual → action ที่ถูกเรียก → ทดลองแก้ → ตรวจซ้ำ ก่อนเพิ่ม สมุดในข้อมูลเดิมมี quantity 2 หลังเพิ่มข้อมูลใหม่ต้องมี quantity 3 แต่ข้อมูลเดิมยังเป็น 2 ลองวาด array และ object ของก่อน/หลังด้วยลูกศร แล้วอธิบายว่า reference ใดถูกใช้ร่วมกัน

เมื่อผ่าน unit แล้วเรียก `npm run check` ให้ผ่านทั้งสองชุด หากเครื่องมือไม่เริ่มหรือ browser ไม่ติดตั้ง ให้แก้การเตรียมเครื่องตาม TOOLING ก่อน อย่าตีความว่าเป็นบั๊กตามโจทย์

ถ้าติดประมาณ 5 นาที จดสิ่งที่คาด สิ่งที่เห็น และสิ่งที่ลอง นาที 10 อ่านความต่าง expected/actual อีกครั้งหรือถามผู้สอน นาที 15 commit งานและบันทึกสิ่งที่ยังไม่เข้าใจเพื่อกลับมาฝึกต่อ ไม่ต้องรีบคัดลอกเฉลย

## 5 นาทีท้าย: อธิบายและวางแผนฝึกต่อ

- [ ] Tests ทุกตัวผ่าน โดยไม่แก้ assertions
- [ ] อธิบายได้ว่าทำไมหน้าจอถูกแต่ข้อมูลเดิมยังอาจผิด
- [ ] อธิบายได้ว่าการสร้าง array ใหม่ต่างจากการสร้าง object ใหม่อย่างไร
- [ ] ชี้ local/store/derived state ในแอปได้ พร้อมเหตุผลของขอบเขต
- [ ] จดหนึ่งพฤติกรรมหรือแนวคิดที่ต้องกลับมาฝึก พร้อมคำสั่งตรวจ

สำเร็จเมื่อ tests ผ่านและตอบเหตุผลครบ ถ้าพฤติกรรมผ่านแต่เหตุผลยังไม่ครบ ให้บันทึกว่า “พฤติกรรมผ่านแล้ว แต่ยังต้องทบทวนแนวคิด” การอ่านเฉลยอย่างเดียวยังไม่นับว่าฝึกสำเร็จ
